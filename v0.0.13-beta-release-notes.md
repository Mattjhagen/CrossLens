# v0.0.13-beta Release Notes — Crash Reporting Integration

**Released:** 2026-09-24  
**Milestone:** Firebase Crashlytics Integration

## What's New

This release integrates Firebase Crashlytics for production crash monitoring and error reporting. Crashes and non-fatal exceptions are automatically logged to Firebase Console, with ProGuard mapping files uploaded for symbolicated stack traces.

### Firebase Crashlytics Integration

- **Automatic crash logging:** Crashes are automatically captured and sent to Firebase Console
- **ProGuard/R8 support:** Mapping files uploaded during release builds for readable stack traces
- **Build type awareness:** Crashlytics enabled only for release builds, disabled for debug
- **Custom crash context:** Build type, version name, and version code included in crash reports
- **Offline support:** Crashes cached locally and uploaded when network available

### Technical Implementation

**Dependencies Added:**
- Firebase BoM 33.5.1 (Bill of Materials for version management)
- Firebase Crashlytics KTX
- Google Services Plugin 4.4.2
- Firebase Crashlytics Gradle Plugin 3.0.2

**Build Configuration:**
- ProGuard mapping file upload enabled for release builds
- Mapping file upload disabled for debug builds
- Crashlytics-specific ProGuard rules added

**Application Initialization:**
- Crashlytics initialized in `CrossLensApplication.onCreate()`
- Enabled only for release builds (`!BuildConfig.DEBUG`)
- Custom keys set: build_type, version_name, version_code

**Firebase Project Setup:**
- Firebase project created: CrossLens
- Two apps registered:
  - `com.crosslens.app` (release)
  - `com.crosslens.app.debug` (debug)
- SHA-256 certificate fingerprint registered
- `google-services.json` configured (gitignored)

## Privacy Considerations

### Data Collected by Crashlytics

Firebase Crashlytics automatically collects:
- ✅ Stack traces (file names, line numbers, method names)
- ✅ Device model, OS version, screen size
- ✅ App version code and name
- ✅ Build type (debug/release)
- ✅ Timestamp of crash
- ✅ Crash-free users percentage

### Data NOT Collected

- ❌ User email or name
- ❌ User IDs
- ❌ Location data
- ❌ Analytics events (Analytics disabled)
- ❌ User preferences or saved data
- ❌ Story content or article text

### GDPR Compliance

**Current status:** Crashlytics runs by default without user consent
- No PII collection (compliant)
- No opt-out mechanism yet (planned)
- Privacy policy not yet updated (required before production)

**Before production release:**
1. Update privacy policy to disclose crash reporting
2. Add opt-out toggle in Settings
3. Implement `FirebaseCrashlytics.setCrashlyticsCollectionEnabled(userChoice)`

## Testing Crash Reporting

### View Crashes in Firebase Console

1. Go to https://console.firebase.google.com
2. Select "CrossLens" project
3. Navigate to Crashlytics in left sidebar
4. View crash reports, affected users, and stack traces

### Test Crash (Debug Build)

Crashlytics is disabled in debug builds, so you'll need to test with a release build:

1. Build release APK (signed)
2. Install on test device
3. Trigger a crash (will require adding test crash button)
4. Reopen app (crashes uploaded on next launch)
5. Wait 5-10 minutes for crash to appear in Firebase Console

## Monitoring Strategy

### Firebase Console

Access crash data at:
- Dashboard: https://console.firebase.google.com/project/crosslens/crashlytics
- Real-time crash alerts
- Crash-free users percentage
- Most impacted devices/OS versions
- Stack traces with line numbers (ProGuard symbolicated)

### Success Metrics

**Target crash-free rate:** 99%+ within 7 days of release

**Response protocol:**
- Critical crashes (>5% users affected): Fix within 24 hours
- High-impact crashes (>1% users): Fix within 3 days
- Low-impact crashes (<1% users): Prioritize with backlog

### Email Alerts

Configure in Firebase Console → Crashlytics → Settings:
- New issue detected
- Regressed issue (previously fixed, now reappearing)
- Velocity alerts (sudden spike in crash rate)
