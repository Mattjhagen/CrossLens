## Architecture Decisions

### 1. Caching Strategy
**Decision:** Show cached feed immediately, refresh in background if stale (>15min)  
**Rationale:** Provides instant app launch experience while keeping data fresh  
**Implementation:** LiveStoryRepository checks cache age on init, spawns background refresh job

### 2. Fallback Hierarchy
**Decision:** Live → Cached → Mock (only if no cache AND all sources fail)  
**Rationale:** Preserves offline utility without misleading users about data source  
**Implementation:** observeStories() prefers live feed stories, falls back to mock only when no live cache

### 3. Per-Source Failure Isolation
**Decision:** One failed source never blocks others  
**Rationale:** Maximizes content availability during partial outages  
**Implementation:** async/await with individual try-catch per adapter, collects all successes

### 4. Room for Caching
**Decision:** Use existing Room database for live feed cache  
**Rationale:** Consistent with existing architecture, no new dependencies  
**Implementation:** Live stories use "live_feed_" ID prefix, distinct from mock stories

### 5. No Automatic Clustering
**Decision:** Show chronological feed, defer event matching  
**Rationale:** Conservative first step, avoids false positive matches  
**Implementation:** One story per RSS item, no cross-source deduplication

## RSS Sources

All four sources verified accessible with valid RSS 2.0 format:

1. **BBC News** - https://feeds.bbci.co.uk/news/rss.xml (UK/Europe, English)
2. **Al Jazeera** - https://www.aljazeera.com/xml/rss/all.xml (Qatar/Middle East, English)
3. **Deutsche Welle** - https://rss.dw.com/xml/rss-en-all (Germany/Europe, English)
4. **France 24** - https://www.france24.com/en/rss (France/Europe, English)

Each source:
- Uses public RSS URL with no authentication
- Provides HTTPS-only content
- Includes headline, description, link, publication date
- Has documented terms of use
- Updates frequently (5-15 minute TTL)

## Error Handling

### Parser Level
- Malformed XML returns Result.failure
- Missing required fields (title, link) filters item out
- Unparseable dates return null (item still included)
- Description truncated to 500 chars
- Max 50 items per feed

### Adapter Level
- 10-second read timeout
- 5-second connection timeout
- 5MB response size limit
- Empty list on any exception
- HTTPS-only URLs

### Repository Level
- Parallel source fetching with individual error handling
- Metadata tracks successful/failed source counts
- Failed refresh preserves existing cache
- UI shows appropriate state (Loading/Live/Cached/Demo/Error)

## Privacy & Safety

- **No credentials:** All RSS URLs are public
- **No tracking:** No analytics, advertising IDs, or passive behavior tracking
- **No location collection:** Source region is publishing context only
- **HTTPS-only:** All requests and original article links use HTTPS
- **Clear attribution:** Each article shows original publisher
- **User-Agent:** Identifies as "CrossLens/0.0.14-beta (Android)"

## Known Issues & Limitations

1. **Database Migration:** V6 schema requires fresh install (destructive migration)
2. **Local Stories Filter:** Live feed doesn't respect "Local Sources" toggle yet
3. **No Deduplication:** Same article may appear from multiple sources
4. **Cache Age Polling:** 30-second poll interval (not real-time)
5. **No WorkManager:** Background refresh only on app init (no scheduled refresh)
6. **English Only:** Multilingual variants exist but not integrated
7. **No Event Clustering:** Articles shown chronologically, not matched across sources
