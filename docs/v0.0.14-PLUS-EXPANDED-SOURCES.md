### Per-Publisher Balancing

**Problem:** With 15 sources, a single prolific publisher could dominate the feed.

**Solution:** 
- Maximum 5 articles per publisher in the visible feed
- Chronological sorting preserved within each publisher's quota
- Applied before story grouping

**Implementation:**
```kotlin
val balancedItems = allItems
    .groupBy { it.first.sourceId }
    .flatMap { (_, items) ->
        items.sortedByDescending { it.second.publishedAt }
            .take(MAX_ARTICLES_PER_PUBLISHER)
    }
    .sortedByDescending { it.second.publishedAt }
```

### Conservative Story Grouping

**Problem:** Multiple publishers often report the same event, but false grouping misleads users.

**Solution:** Conservative matching with three strict criteria:
1. **Normalized title similarity > 70%** (Jaccard similarity of word sets)
2. **Published within 6 hours** of each other
3. **Same canonical URL** (exact match)

When uncertain, articles remain separate.

**Implementation:**
- Normalize titles: lowercase, remove punctuation, split into words
- Calculate Jaccard similarity: `intersection / union` of word sets
- Time proximity check: `abs(time_diff) <= 6 hours`
- URL exact match (canonical link comparison)

**UI Display:**
- Stories show "N sources" where N = number of grouped articles
- Single-article stories show "1 source"
- User sees clear source attribution for grouped stories

### Known Limitations

1. **No LLM-based semantic matching:** Current grouping uses word-level Jaccard similarity, may miss semantically similar but lexically different headlines
2. **Fixed thresholds:** 70% similarity and 6-hour window are constants, not adaptive
3. **No language normalization:** Spanish/Japanese headlines compared as-is (works for exact URL matches only)
4. **No publisher weighting:** All sources treated equally in grouping logic
5. **No user customization:** Cannot disable specific sources or adjust per-source limits

### Future Enhancements

- **Semantic similarity:** Use embeddings or LLM for better cross-lingual matching
- **Adaptive thresholds:** Learn optimal similarity threshold from user feedback
- **Per-source configuration:** User can enable/disable sources, set per-source limits
- **Language normalization:** Translate headlines to common language for comparison
- **Publisher metadata:** Track reliability, update frequency, paywall status per source

### Regression Risk Assessment

**Low Risk Changes:**
- Source expansion is additive (existing 4 sources unchanged)
- Per-publisher balancing only affects display order (no data loss)
- Conservative grouping errs on side of keeping stories separate

**Medium Risk:**
- Story grouping logic introduces new code path (groupArticlesByConservativeSimilarity)
- Multiple articles per story changes UI expectations (articleIds.size > 1)

**Mitigation:**
- Existing 4 sources continue to work as before
- Grouping threshold (70%) is conservative to avoid false positives
- UI already handles multiple articleIds per story (no changes needed)
